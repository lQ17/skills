## ⚠️ 输出约束铁律（新增）

**生成随机数据时，必须保证标程在该数据上的输出符合题面声明的所有约束。**

反例（P1063 能量项链）：
- 题面声明 $E \\le 2.1 \\times 10^9$
- 但 N=100 + 全值 1000 → 答案 800 亿 → **违反约束**
- **正确做法**：大规模数据时缩小值范围（N=100 时值 ≤ 200），确保答案在声明范围内

### 约束合规检查清单

在编写 mkin.h 的 test() 函数时，对每组随机数据：

| 检查项 | 说明 |
|--------|------|
| 输入合规 | N、a_i 等在题面声明的输入范围内 |
| 输出上界 | 答案不超过题面声明的最大值（如 $E \\le 2.1 \\times 10^9$） |
| 输出格式 | 输出行数、每行元素数符合题面要求 |
| 答案类型 | 整数/浮点数类型正确 |

⚠️ **大规模数据（case 16-25）尤其容易违反输出上界**，必须用小值或中等规模生成，不可盲目使用题面声明的输入最大值组合。

## ⚠️ Hack 数据设计铁律：基于风险目录，非凭感觉

### 旧做法（❌ 禁止）

```cpp
else if (case_num == 9) {
    // Hack: int 溢出（通用模板，不分析本题是否需要）
    fout << 2 << endl;
    fout << "2147483647 2147483647" << endl;
}
```

### 新做法（✅ 必须）

```cpp
// 从 boundary.md 风险 #2 读取：
// 风险：两数之和可能超过 int 范围
// 触发条件：a + b > 2^31-1
// 最低难度：SILVER | 当前题 BRONZE → ❌ 不测
// → 此题不生成此 Hack 数据，该 case 位用于其他风险

// 从 boundary.md 风险 #3 读取：
// 风险：a_i == K 时 > 与 ≥ 混淆
// 触发条件：存在 a_i 恰好等于 K
// 最低难度：BRONZE | 当前题 BRONZE → ✅ 需测
else if (case_num == 9) {
    // Hack: 风险 #3 — a_i == K 时 > 与 ≥ 混淆
    // 构造：所有 a_i 都等于 K，答案应为 0（>K 的个数）
    int N = 5, K = 10;
    fout << N << " " << K << endl;
    for (int i = 0; i < N; i++) fout << K << " \n"[i==N-1];
}
```

### Hack 数据映射规则

1. **只使用 boundary.md 中标 ✅ 的风险**设计 Hack 数据
2. **每个 ✅ 风险至少对应 1 组 Hack 数据**
3. 标 ❌ 的风险**禁止**出现在 Hack 数据中（会超出题目难度设计意图）
4. 如果 ✅ 风险数量 < 3 个，多余的 Hack case 位用于**随机小规模**数据
5. 如果 ✅ 风险数量 > 3 个，优先覆盖**最低难度最低**的风险（最基本的要求）

## 特殊性质数据设计

特殊性质数据同样**必须来自 boundary.md 中 ✅ 的风险条目**。

| 性质 | 说明 | 最低难度 | 当前题是否设计 |
|------|------|---------|-------------|
| 单调性 | 输入有序（递增/递减） | BRONZE | 看 boundary.md |
| 值皆同 | 数组诸元相等 | BRONZE | 看 boundary.md |
| 二分图质 | 特定图结构 | SILVER | 看 boundary.md |
| 素数密 | 大量素数 | SILVER | 看 boundary.md |
| 极值 | 极大/极小可能值 | BRONZE | 看 boundary.md |

⚠️ **不再使用通用模板**，每个特殊性质 case 都需标注对应 boundary.md 中的风险编号。
