# Step 8.5: 独立对拍验证 + 输出约束检查

## 目标

测试数据生成完成后，**用独立实现的代码和输出约束进行双重验证**，确保数据正确、合规。失败数据自动重新生成。

## 前置依赖

- `{WORK_DIR}/testcases/`：已生成的全部测试数据（.in + .out）
- `{WORK_DIR}/std.cpp`：已通过样例和边界验证的标程
- `{WORK_DIR}/problem.md`：完整题面（含数据范围、输出约束）
- `{WORK_DIR}/boundary.md`：风险目录

---

## ⚠️ 核心原则

```
数据正确性 = 独立验证（不同思路重写） + 约束合规检查（输出在题面声明范围内）
只靠 std.cpp 自证 = 无效验证
```

---

## 第一步：提取输出约束

从 `{WORK_DIR}/problem.md` 中读取题面的**所有约束**，特别关注：

### 输入端约束（已在 boundary.md 中覆盖）
- N 的范围、a_i 的范围
- 特殊限制（如"所有数不超过 X"）

### 输出端约束（⚠️ 新增，此前被忽略）
- **答案上界**：题面声明的输出上界（如"$E \\le 2.1 \\times 10^9$"）
- **答案下界**：题面声明的输出下界（如"保证答案为非负整数"）
- **输出格式**：输出行数、每行格式
- **精度要求**：浮点数精度（如"保留 X 位小数"）
- **特殊保证**：题面中任何对输出范围的声明（含"提��/说明"节）

将这些写入 `{WORK_DIR}/constraints.json`：

```json
{
    "max_answer": 2100000000,
    "output_lines": 1,
    "output_value_range": [0, 2100000000]
}
```

**填写规则**：
- 若题面声明了输出上界（如 $E \\le 2.1 \\times 10^9$），填入 `max_answer`
- 若声明了输出元素个数（如"输出共 2 行"），填入 `output_lines`
- 若声明了单个输出值的范围，填入 `output_value_range`
- 若题面无明确声明，对应字段设为 `null`

---

## 第二步：独立实现验证器

**不看 std.cpp 的内容**，仅根据 `{WORK_DIR}/problem.md` 中的题目描述，独立编写一份验证程序 `{WORK_DIR}/validator.cpp`。

### 编写要求

1. **换算法**：用与 std.cpp 不同的实现思路
   - 若 std 是 DP 递推 → validator 用记忆化搜索 / 暴搜
   - 若 std 用数学公式 → validator 用模拟 / 枚举
   - 若题目有多种解法 → 用第二种解法
2. **降复杂度也无妨**：validator 不必追求最优复杂度，正确性优先
   - 小数据（N ≤ 20）用暴力
   - 大数据可用相同算法但不同实现风格
3. **必能过全部数据**：validator 须对全部 testcases/*.in 正确输出

### 若用户提供了标程

**优先使用用户提供的标程作为 validator**，将其复制到 `{WORK_DIR}/validator.cpp`。

### 若题目过于简单（BRONZE 及以下）

可跳过独立重写，直接进入第三步（约束检查）。validator 可与 std 使用相同算法。

---

## 第三步：运行对拍验证

使用 `{QUESTION_TEMPLATE}/check.py` 脚本：

```bash
cd {WORK_DIR}
python check.py --validator validator.cpp --constraints constraints.json
```

脚本自动：
1. 编译 std.cpp → `std_chk`
2. 编译 validator.cpp → `validator_chk`
3. 逐组运行两个程序，比对输出
4. 检查每组输出是否符合 `constraints.json` 中的约束
5. 报告所有失败项

---

## 第四步：处理失败

对拍或约束检查失败的测试用例，**必须重新生成**，不得直接保留。

### 对拍失败（std ≠ validator）

说明 std 或 validator 至少有一个错误。处理流程：

1. 人工判断哪个输出正确
2. 修复错误的程序
3. 重新编译、重新对拍
4. 若测试数据本身有问题（输入超出约束 → 导致双方都错），**修改 mkin.h 中该 case 的数据生成逻辑**，缩小参数范围
5. 重新运行 mkdata 生成数据
6. 重新运行 check.py，直到全部通过

### 约束违反（输出超出题面声明范围）

说明生成的数据**参数过大**，处理流程：

1. 识别违规的测试用例编号
2. 修改 `mkin.h` 中对应 case 的数据生成代码：
   - 缩小 N 的范围
   - 缩小 a_i 的取值范围
   - 确保 std 在该输入上的答案 ≤ 题面声明的上界
3. 重新运行 `./mkdata`
4. 重新运行 check.py，直到全部通过

### 重试上限

最多重试 3 轮。若 3 轮后仍有失败，标记该 case 为"需人工介入"，在最终报告中说明。

## 验证模板

### constraints.json 示例（P1063 能量项链）

```json
{
    "max_answer": 2100000000,
    "output_lines": 1,
    "output_value_range": [0, 2100000000]
}
```

### validator.cpp 示例（P1063 能量项链 — 用暴力枚举验证）

```cpp
// validator.cpp：用不同的实现方式验证
#include <bits/stdc++.h>
using namespace std;

int n, a[210];
long long ans;

void dfs(int cnt, vector<int> v, long long cur) {
    if (v.size() == 1) {
        ans = max(ans, cur);
        return;
    }
    for (int i = 0; i + 1 < (int)v.size(); i++) {
        int new_head = v[i];
        int new_tail = v[i+2 < (int)v.size() ? i+2 : i+1]; // simplified
        long long gain = 1LL * v[i] * v[i+1] * v[(i+2) % (int)v.size()];
        vector<int> nv;
        for (int j = 0; j < (int)v.size(); j++)
            if (j != i && j != i+1) nv.push_back(v[j]);
        // insert merged bead
        nv.insert(nv.begin() + i, new_head);
        dfs(cnt + 1, nv, cur + gain);
    }
}

int main() {
    ios::sync_with_stdio(false);
    cin >> n;
    vector<int> v;
    for (int i = 1; i <= n; i++) {
        cin >> a[i];
        v.push_back(a[i]);
    }
    // 破环成链：枚举起点
    long long best = 0;
    for (int s = 0; s < n; s++) {
        ans = 0;
        vector<int> ring;
        for (int i = 0; i < n; i++) ring.push_back(a[1 + (s + i) % n]);
        dfs(0, ring, 0);
        best = max(best, ans);
    }
    cout << best;
    return 0;
}
```
